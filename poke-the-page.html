React · events · ELI5

Events are just pokes.

A page is full of things you can poke — buttons, boxes, keys. Poke one and you've made an event. You get to say what happens next.

This page uses plain JavaScript to show the idea. React does the same thing with onClick.

01

Every poke has a name.

Click, type, press a key, send a form — the browser names each poke, and React listens.

TYPEonChange
KEYonKeyDown
HOVERonMouseEnter
SUBMITonSubmit
02

Stick a note on the thing.

You decide what each poke does. Stick a tiny note on the button that says what should happen.

<button onClick={sayHello}> Poke me </button> // "when clicked, run sayHello"
03

Hand the note over. Don't read it now.

onClick wants the note itself. If you put (), you read it out loud right away — before anyone clicks.

04

The poke comes with a backpack.

Every event carries facts: which key, where you clicked. React hands the backpack to your note as e.

backpack: nothing yet

onKeyDown={(e) => console.log(e.key)} // type above — the backpack is being read
05

React makes its own copy.

Every browser pokes a little differently. React copies each poke into one standard shape — a synthetic event — so your note reads the same backpack on any device.

onClick={(e) => readThe(e)} // e is React's copy — the synthetic event // the original poke is tucked inside: e.nativeEvent
06

One listener at the top.

You stick a note on each thing. But React doesn't put an ear on every thing — it puts one listener at the top, and every poke bubbles up to it.

// you write this — a note on each thing <button onClick={sayHello}>Poke me</button> // React does this for you — one listener at the top // listens once · catches every poke · runs the right note
07

Then the page redraws.

Your note runs, and React draws the page again with the new answer. That little loop is the whole game.

That's it. That's React events.
